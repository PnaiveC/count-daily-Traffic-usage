## 1. 项目背景与目标

### 1.1 背景

当前 Android
系统自带的流量统计以"月度计费"为核心，用户只能看到本月总量和当月按应用排行，**无法方便地查看每天、每周的流量消耗，也无法查看每个应用在每一天的具体用量**。第三方工具又普遍存在广告多、功能臃肿、权限要求过度等问题。

### 1.2 目标

开发一个极简的 Android App，满足以下核心需求：

-   查看**今日 / 本周 / 本月**的总流量消耗（移动 + Wi-Fi）。
-   查看**每个应用**在今日 / 本周 / 本月的流量消耗，并按用量排序。
-   完全无广告、无联网、无账号，所有数据本地读取。

### 1.3 范围

**MVP
包含**：流量概览、应用消耗列表、时间范围切换、权限引导、设置与关于。\
**MVP 不包含**：实时悬浮窗、网速显示、流量限额提醒、防火墙、多 SIM
卡区分、云同步、历史数据长期存储（后续可加）。

## 2. 用户与场景

### 2.1 目标用户

-   关心自己每天 / 每周流量去向的普通用户。
-   不想被广告打扰、注重隐私的用户。
-   开发者本人自用。

### 2.2 典型场景

-   晚上想看看今天哪个 App 偷跑了流量。
-   周一想知道上周哪些应用消耗最多。
-   发现流量异常，快速定位是哪个应用在后台消耗。

## 3. 功能需求

### 3.1 权限引导（F1）

-   **F1.1** 首次打开 App
    时，检查是否已获得"使用情况访问权限"（`PACKAGE_USAGE_STATS`）。
-   **F1.2** 权限检查必须兼容 API 23\~28 与 API 29+：
    -   API 29+ 使用 `unsafeCheckOpNoThrow`。
    -   API 23\~28 使用 `checkOpNoThrow`。
    -   返回 `AppOpsManager.MODE_ALLOWED` 视为已授权。
-   **F1.3**
    若未授权，显示说明页，解释为什么需要该权限，并提供按钮跳转到系统设置页。优先使用
    `Settings.ACTION_USAGE_ACCESS_SETTINGS`；跳转失败时回退到应用详情设置页，并附常见厂商路径文字说明。
-   **F1.4** 授权后返回 App，在 `onResume`
    中重新检查权限，并自动刷新数据。
-   **F1.5** 若用户拒绝授权，显示空状态提示，不崩溃。
-   **F1.6** 关于页显示当前权限状态，并可再次跳转授权页。

### 3.2 流量概览（F2）

-   **F2.1** 首页顶部显示三个周期卡片或数字：
    -   今日总用量（移动 + Wi-Fi）
    -   本周总用量
    -   本月总用量
-   **F2.2** 当前选中的时间范围对应卡片高亮；每个数值旁可显示移动 /
    Wi-Fi 的细分小字。
-   **F2.3** 总用量按本 App 的统计口径计算为移动数据 + Wi-Fi。分别通过
    `NetworkStatsManager.querySummaryForDevice` 查询。该结果是 Android
    系统维护的统计值，不承诺与运营商计费完全一致，也不保证精确切分任意时间边界。
    -   `ConnectivityManager.TYPE_MOBILE`
    -   `ConnectivityManager.TYPE_WIFI`
    -   `subscriberId` 传 `null`
    -   结果取 `rxBytes + txBytes`
-   **F2.4** 查询返回
    `null`、抛出异常或权限不足时，不能仅将对应数值显示为真实的
    0。必须同时保留查询状态（成功、无可用记录、权限不足、读取失败）；仅在查询成功且用量确为
    0 时显示 0。不能崩溃。
-   **F2.5** 数据随下拉刷新、时间范围切换、从系统设置返回后自动更新。
-   **F2.6** 单位自动转换：KB / MB / GB。

### 3.3 应用消耗列表（F3）

-   **F3.1** 按当前选中的时间范围（今日 / 本周 /
    本月），列出系统查询结果中可识别且有流量消耗的应用；对无法映射到已安装应用的
    UID，按约定显示 UID/系统条目或在列表中单独说明，不得静默丢弃。
-   **F3.2** 每行显示：应用图标、应用名称、该周期内总用量、移动 / Wi-Fi
    细分（可选）。
-   **F3.3** 默认按总用量从高到低排序。
-   **F3.4** 点击某一行，进入应用详情页，显示该应用在今日 / 本周 /
    本月的移动和 Wi-Fi 分开用量。
-   **F3.5** 列表支持下拉刷新。
-   **F3.6** 查询和聚合必须在 IO 线程执行，不能阻塞主线程。
-   **F3.7** 按 UID 聚合移动与 Wi-Fi 流量；共享 UID
    的多个应用合并显示为一个条目。若 UID
    对应多个包，应显示可解释的合并名称（如"多个应用"），不可未经验证地仅用第一个包名代表全部应用。
-   **F3.8** 应用无图标时使用默认图标兜底；`PackageManager`
    查询失败时显示包名或 `UID xxx`。
-   **F3.9** 无数据时显示"暂无流量记录"。
-   **F3.10**
    查询失败时显示"读取失败，请检查权限或稍后重试"；权限不足、无记录与读取失败应区分展示。

### 3.4 时间范围切换（F4）

-   **F4.1** 提供"今日 / 本周 / 本月"三个切换按钮。
-   **F4.2** "今日"指设备当前时区下当天 0:00
    至查询时刻。系统统计的时间桶/保留策略可能导致边界并非精确到分钟。
-   **F4.3** "本周"指设备当前时区下本周一 0:00
    至查询时刻。系统统计的时间桶/保留策略可能导致边界并非精确到分钟。
-   **F4.4** "本月"指设备当前时区下本月 1 日 0:00
    至查询时刻。系统统计的时间桶/保留策略可能导致边界并非精确到分钟。
-   **F4.5** 切换后，概览和应用列表同步更新。
-   **F4.6** 时间计算必须兼容 API 23。可使用 `Calendar`，或开启 Java 8+
    API Desugaring 后使用 `java.time`。建议封装
    `TimeRangeProvider`，并单独测试"周一""月初""跨年"等边界。
-   **F4.7** 部分 ROM
    系统历史数据保留较短，超出保留范围的数据可能无法读取。界面可提示"系统仅保留近期记录"。

### 3.5 设置与关于（F5）

-   **F5.1** 显示当前权限状态，可再次跳转授权页。
-   **F5.2** 显示版本号。
-   **F5.3** 显示"本应用无广告、无联网、数据仅存本地"的声明。
-   **F5.4** 可选：提供"清除本地缓存"按钮（若后续加入 Room 数据库）。
-   **F5.5** 显示已知限制说明：双卡暂不区分、共享 UID
    会合并显示、系统历史数据可能保留较短、App 不申请 `INTERNET` 权限。

## 5. 技术方案概要

### 5.1 技术栈

-   **语言**：Kotlin
-   **UI**：XML + ViewBinding 优先，便于控制 APK 体积；Jetpack Compose
    可选，但需注意体积和冷启动。
-   **架构**：单 Activity + ViewModel + Repository
-   **数据源**：`NetworkStatsManager`（系统流量统计服务）
-   **应用信息**：`PackageManager`
-   **本地持久化**：MVP 可不用；若需长期历史，后续引入 Room
-   **异步**：Kotlin Coroutines + Flow / LiveData

### 5.2 核心 API

#### 权限检查

``` kotlin
val appOps = getSystemService(AppOpsManager::class.java)
val mode = if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.Q) {
    appOps.unsafeCheckOpNoThrow(
        AppOpsManager.OPSTR_GET_USAGE_STATS,
        Process.myUid(),
        packageName
    )
} else {
    @Suppress("DEPRECATION")
    appOps.checkOpNoThrow(
        AppOpsManager.OPSTR_GET_USAGE_STATS,
        Process.myUid(),
        packageName
    )
}
val granted = mode == AppOpsManager.MODE_ALLOWED
```

#### 查询总流量

``` kotlin
val networkStatsManager = getSystemService(NetworkStatsManager::class.java)

fun queryDeviceTotal(type: Int, startTime: Long, endTime: Long): Long {
    return try {
        val bucket = networkStatsManager.querySummaryForDevice(
            type, // ConnectivityManager.TYPE_MOBILE 或 TYPE_WIFI
            null,
            startTime,
            endTime
        )
        if (bucket == null) 0L else bucket.rxBytes + bucket.txBytes
    } catch (e: SecurityException) {
        0L
    } catch (e: RemoteException) {
        0L
    } catch (e: Exception) {
        0L
    }
}
```

总用量 = 移动数据 + Wi-Fi。

#### 查询按应用流量

``` kotlin
fun queryAppStats(type: Int, startTime: Long, endTime: Long): Map<Int, Long> {
    val result = mutableMapOf<Int, Long>()
    try {
        val stats = networkStatsManager.querySummary(
            type,
            null,
            startTime,
            endTime
        ) ?: return result

        while (stats.hasNextBucket()) {
            val bucket = NetworkStats.Bucket()
            stats.getNextBucket(bucket)
            val uid = bucket.uid
            val bytes = bucket.rxBytes + bucket.txBytes
            result[uid] = (result[uid] ?: 0L) + bytes
        }
    } catch (e: SecurityException) {
        // 未授权
    } catch (e: RemoteException) {
        // 系统服务异常
    } catch (e: Exception) {
        // 其他异常
    }
    return result
}
```

移动和 Wi-Fi 分别查询后，按 UID 合并。再通过 `PackageManager`
映射应用名称、图标。

### 5.3 权限声明

``` xml
<uses-permission android:name="android.permission.PACKAGE_USAGE_STATS"
    tools:ignore="ProtectedPermissions" />
```

**注意**：该权限不能通过运行时弹窗授予，必须引导用户到"设置 → 应用 →
特殊应用权限 → 使用情况访问"手动开启。

**不声明**：

``` xml
<uses-permission android:name="android.permission.INTERNET" />
```

若依赖合并后发现 `INTERNET` 被引入，需显式移除。

### 5.4 数据刷新策略

-   打开 App 时自动查询。
-   下拉刷新时重新查询。
-   切换时间范围时重新查询。
-   从系统设置返回 App 时重新检查权限并刷新。
-   MVP 不做后台常驻服务。
-   所有查询放 `Dispatchers.IO`，UI 只接收结果。

### 5.5 异常与边界处理

-   `SecurityException`：提示未授权或权限失效。
-   `RemoteException`：提示读取失败，请稍后重试。
-   `NetworkStats` / `Bucket` 为 `null`：跳过或按 0 处理。
-   共享 UID：合并为一个条目，正常现象。
-   无图标应用：使用默认图标。
-   双卡设备：`subscriberId` 传 `null`，只统计总移动数据，不区分 SIM
    卡。
-   系统历史数据保留短：界面提示"系统仅保留近期记录"。

-   **不申请** `INTERNET` 权限，从源头杜绝联网上传。

-   最终 APK 需检查合并后的 Manifest，确保无 `INTERNET` 权限。

## 11. 技术评审补充与实施约束（v0.3）

本节用于明确 MVP
实施时必须遵守的统计语义、状态处理和验证方式。`NetworkStatsManager`
读取的是 Android
系统维护的网络使用统计；它适合历史用量审计，不等同于实时抓包，也不保证与运营商账单完全一致。

### 11.1 查询结果与 UI 状态

Repository 不应仅返回 `Long` 或空 Map，并把所有异常折算成
0。建议至少区分：

-   `Success(data)`：查询成功，数据可能为 0。
-   `NoData`：查询成功，但当前范围没有可用记录（若 API
    无法可靠区分，应由实现定义并记录语义）。
-   `PermissionDenied`：权限未授予或查询因权限失败。
-   `Failure`：系统服务异常、查询失败或其他未预期错误。

UI
应分别呈现加载中、成功、无记录、权限不足和读取失败。日志只记录排障所需的错误类型，不记录不必要的个人数据。任何错误路径均不得导致崩溃。

### 11.2 统计口径与数据一致性

1.  设备总量与按 UID
    查询属于不同查询路径。不能假设应用列表各行求和必然等于设备总量。
2.  测试时应比较设备总量、可映射 UID
    合计及差额；差额应作为诊断信息，不应通过人为调整某个应用用量来"凑平"。
3.  应明确是否显示系统 UID、无法映射的
    UID、已卸载应用留下的统计项。不得静默丢弃可能影响解释的条目。
4.  移动网络与 Wi-Fi
    分开查询后再按产品定义合并。双卡设备的移动网络结果需实机验证；MVP
    不承诺 SIM 卡维度。
5.  系统统计可能采用时间桶或受到系统历史保留策略影响，因此"今日/本周/本月"是查询时间范围定义，不代表系统能精确提供任意时刻的计量值。

### 11.3 应用与 UID 映射

-   一个 UID 可能对应多个包名；共享 UID
    应合并展示，并以"多个应用"或可解释的名称呈现。
-   对无法通过 `PackageManager` 解析的 UID，应按产品规则显示
    UID/系统条目，或明确说明不纳入应用明细；该规则需在测试中覆盖。
-   Android 11+
    的包可见性可能影响应用信息查询。开发时应验证目标包是否可见；仅在确有必要且符合平台要求时添加包可见性声明。
-   图标或名称获取失败不得影响流量数据本身的展示。

### 11.4 时间范围实现与测试

建议使用统一的 `TimeRangeProvider`，以设备当前时区计算：

-   今日：当天 00:00 至查询时刻。
-   本周：周一 00:00 至查询时刻。
-   本月：当月 1 日 00:00 至查询时刻。

可使用 `java.time` 并配置 Java API Desugaring，或使用
`Calendar`。需测试周一、月初、跨年、闰年、时区变更及午夜刷新。时间范围计算正确，不代表系统网络统计的时间桶边界也能精确到同一时刻。

### 11.5 建议的轻量架构

保持单 Activity + ViewModel + Repository，不要求首版引入多模块或大型 DI
框架。建议职责如下：

-   `TimeRangeProvider`：计算时间范围。
-   `NetworkStatsDataSource`：封装 `NetworkStatsManager` 查询。
-   `PackageDataSource`：封装应用名称、图标及 UID/包名映射。
-   `NetworkStatsRepository`：协调查询、合并移动/Wi-Fi
    数据、处理状态与排序。
-   `ViewModel`：管理页面状态、刷新和时间范围切换。
-   UI：只展示状态和数据，不在主线程执行查询、包信息读取或排序。

可使用 Coroutines + `viewModelScope` +
`StateFlow`。依赖注入首版可采用构造函数手动注入。

### 11.6 开发前置验证与测试矩阵

在完成完整 UI 前，先制作最小原型，验证：

-   使用情况访问权限的检测、授予、撤销及从设置返回后的刷新。
-   移动网络、Wi-Fi、双卡、无网络、无历史数据等情境。
-   查询异常与真实零流量的状态区分。
-   应用包名/图标映射失败、共享 UID、系统 UID 和无法映射 UID。
-   今日、本周、本月的时间边界测试。
-   最终 Release APK 的合并 Manifest 不含 `INTERNET` 权限；APK
    体积以实际构建结果验收。

### 11.7 验收口径补充

-   正确性以目标设备上系统 API 返回的数据及本 App
    明确的统计口径为准，不要求与运营商账单完全一致。
-   性能目标为优化目标：查询必须异步执行并提供加载状态；系统 API
    耗时超过 500ms 不应直接判定功能失败。
-   不把"应用列表通常不少于 10
    个"作为正确性要求，因为实际安装应用和系统可提供的记录数量因设备而异。
